# RL25 hardware receiver

RL25 is IPCom v5 delivered on dedicated, prevalidated hardware. It runs the Linux edition, and its web interface and configuration are the same as any other IPCom v5 Linux deployment — so the rest of this IPCom section describes how to operate it. This page covers only what is specific to the hardware unit.

Some material elsewhere in this section does not apply to RL25:

- The Windows `.exe` access flow in [Access and login](./ui/access-and-login.md).
- The Windows column of the [capability comparison](./index.md#capability-comparison-by-deployment) in the overview.
- The server sizing and operating-system requirements in the overview. Those are for building your own Linux server; RL25 arrives with that work done.

## Form factors

| Variant | Description |
| --- | --- |
| RL25 Compact | Standalone unit |
| RL25 Rack | 19-inch rack-mounted unit |

Both variants run the same IPCom v5 software.

## What ships preconfigured

RL25 arrives ready to receive events. Compared with a Windows or Linux installation, the following are already done for you:

- Linux operating system installed and configured
- IPCom v5 installed
- SSD and RAM preinstalled

You do not install an operating system, prepare a server, or run an installer.

### Event output

RL25 supports the full IPCom v5 output set. In the [Outputs tab](./ui/screens/outputs.md) you choose an output `Type` and, for the types that carry CMS traffic, a `Protocol`.

Types: `TCP`, `TCP Server`, `COM Port`, `JSON Server`, `Webhook`.

Protocols: `Surgard MLR2`, `Surgard MLR2 8`, `Surgard MLR2 No End`, `Surgard MLR2 Line with Account`, `SurgardMRL2000 CID`, `Monas 3`, `Ademco 685`, `Ademco 685 CID`, `SIA DC-09`.

Writing events to a MySQL database is configured separately, under `Database settings` in the [General tab](./ui/screens/general.md) — not in `Outputs`.

## Capabilities compared with other deployments

RL25 runs the Linux edition, so it carries the Linux feature set — including the Protegus 2 relay, which the Windows installation does not provide. See the [capability comparison](./index.md#capability-comparison-by-deployment) in the IPCom overview for the full table.

## Connecting for the first time

> [!IMPORTANT]
> Before you start, obtain the unit's network address and management port from TRIKDIS support or from the documentation delivered with your unit. You cannot reach the web interface without them, and this page does not specify them.

Physical installation — which Ethernet port to use for management, the power connector, and what is supplied in the box — is covered by the instructions delivered with the unit. Follow those, then:

1. Open the IPCom Control web interface in a browser at the address and port you obtained above.
2. Sign in — see [Access and login](./ui/access-and-login.md).

## After the first login

Work through these in order to get a new receiver into service:

1. [Status](./ui/screens/status.md) — confirm the unit is healthy and reachable.
2. [General](./ui/screens/general.md) — review API and database options, and configure them if your deployment needs them.
3. [Receivers](./ui/screens/receivers.md) — define the receiver lines that accept device events.
4. [Outputs](./ui/screens/outputs.md) — route events to your monitoring software.
5. [Users](./ui/screens/users.md) — create named operator accounts for daily work, and reserve `administrator` for break-glass use.

Review [Networking and firewall](./ui/networking-firewall.md) before exposing the unit beyond a trusted network.
