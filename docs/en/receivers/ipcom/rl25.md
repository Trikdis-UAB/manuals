# RL25 hardware receiver

RL25 is IPCom v5 delivered on dedicated, prevalidated hardware. It runs the Linux edition, and the web interface is largely the same as any other IPCom v5 Linux deployment — so the rest of this IPCom section describes how to operate it. This page covers what is specific to the hardware unit, including the one screen RL25 has that other deployments do not.

Some material elsewhere in this section does not apply to RL25:

- The Windows `.exe` access flow in [Access and login](./ui/access-and-login.md).
- The Windows column of the [capability comparison](./index.md#capability-comparison-by-deployment) in the overview.
- The server sizing and operating-system requirements in the overview. Those are for building your own Linux server; RL25 arrives with that work done.
- The [General](./ui/screens/general.md) page describes a non-RL25 deployment, so it does not show the `Network settings` section covered below.

## Form factors

| Variant | Description |
| --- | --- |

Both variants run the same IPCom v5 software.

## What ships preconfigured

RL25 arrives ready to receive events. Compared with a Windows or Linux installation, the following are already done for you:

- Linux operating system installed and configured
- IPCom v5 installed
- SSD and RAM preinstalled

You do not install an operating system, prepare a server, or run an installer.

### Event output

RL25 supports the full IPCom v5 output set. In the [Outputs tab](./ui/screens/outputs.md) you choose an output `Type` and, for the types that carry CMS traffic, a `Protocol`.

Types: `TCP`, `TCP Server`, `COM Port`, `JSON Server`, `Webhook`.

Protocols: `Surgard MLR2`, `Surgard MLR2 8`, `Surgard MLR2 No End`, `Surgard MLR2 Line with Account`, `SurgardMRL2000 CID`, `Monas 3`, `Ademco 685`, `Ademco 685 CID`, `SIA DC-09`.

Writing events to a MySQL database is configured separately, under `Database settings` in the [General tab](./ui/screens/general.md) — not in `Outputs`.

RL25 runs the Linux edition, so it carries the Linux feature set — including the Protegus 2 relay, which the Windows installation does not provide. See the [capability comparison](./index.md#capability-comparison-by-deployment) in the IPCom overview for the full table.

## Connecting for the first time

Both Ethernet interfaces are identical and both use DHCP. No interface is dedicated to management — IPCom is reached at whatever address your DHCP server assigns, on the same TCP port whichever interface you use.

Before you begin:

- **The unit needs DHCP to be reachable the first time.** It has no documented fixed address out of the box, so on a network without a DHCP server you will not be able to reach it at all.
- **Check power requirements against the documentation for your unit** before connecting anything. This page does not specify the connector or whether a supply is included; contact TRIKDIS support if you do not have that information.

1. Connect the unit to your network with an Ethernet cable, using either interface.
2. Apply power.
3. Find the address assigned to the unit, from your router's or DHCP server's client list.
4. Open `https://<address>:30003` in a browser. TCP port `30003` is IPCom's default for HTTPS; `8080` is the default for HTTP.
5. Sign in — see [Access and login](./ui/access-and-login.md).

> [!TIP]
> Leaving the unit on a plain DHCP lease means its address can change when the lease is renewed, and the receiver moves without warning. Either reserve its address on your DHCP server, or give it a fixed address in `Network settings`.

Physical installation details — the power connector and what is supplied in the box — are covered by the instructions delivered with the unit.

## Network settings

The `General` tab on an RL25 has a `Network settings` section that does not appear on Windows or self-installed Linux deployments, where the operating system owns the network configuration. It requires the `network_settings` user permission.

> [!WARNING]
> Plan the change before you make it. Decide the address, prefix, gateway and DNS values in advance, confirm the new address is reachable from where you are working, and make sure you have another way onto the unit's network if it is not. Changing the settings of the interface you are connected through will drop your session.

You need an account with the `network_settings` permission. Each interface is listed by name with a `DHCP` toggle; turning `DHCP` off reveals the fixed-address fields:

| Field | Purpose |
| --- | --- |
| `IP address` | The fixed address for this interface |
| `Prefix` | Network prefix length, for example `24` for a `255.255.255.0` mask |
| `Gateway` | Default gateway |
| `DNS 1`, `DNS 2` | Name servers |

After you apply a change, IPCom runs a verification step and reports whether it could confirm the unit on the new settings. Treat that as a signal, not a guarantee — confirm access yourself through the new address before you rely on it.

## Restoring factory defaults

Restoring defaults is a software function, performed from within IPCom Control. There is no hardware reset button on the unit.

> [!WARNING]
> A restore returns IPCom to factory settings, so the configuration on the unit is lost. Do not run it on a receiver that is in service.

IPCom reports that it is then reachable on its default ports: `8080` for HTTP and `30003` for HTTPS. Confirm how the unit is addressed after a restore before relying on a particular address — check your DHCP server's client list if you cannot reach it where you expect.

## After the first login

Work through these in order to get a new receiver into service:

1. [Status](./ui/screens/status.md) — confirm the unit is healthy and reachable.
2. [General](./ui/screens/general.md) — review API and database options, and configure them if your deployment needs them.
3. [Receivers](./ui/screens/receivers.md) — define the receiver lines that accept device events.
4. [Outputs](./ui/screens/outputs.md) — route events to your monitoring software.
5. [Users](./ui/screens/users.md) — create named operator accounts for daily work, and reserve `administrator` for break-glass use.

Review [Networking and firewall](./ui/networking-firewall.md) before exposing the unit beyond a trusted network.
